# 剧情系统：接口速查

面向**在本工程里调用剧情系统的人**。想知道剧情图怎么写，看编辑器工程的
`DarmaViewEditor/Docs/剧情系统-节点使用手册.md`。

代码位置：`Assets/Scripts/XFramework/C#/Drama/`，总入口是 `DramaManager`（`MonoSingleton`）。
数据结构和流程在包 `com.lumino.drama.runtime` 里，本工程只写"长什么样"。

---

## 一、播一段剧情

```csharp
// 剧情ID 是配置表 DramaData 的 ID，剧本资产路径由那张表给出
DramaManager.Instance.StartDramaRuntime(10001);

// 中途打断（玩家退出）
DramaManager.Instance.StopDramaRuntime();
```

`StartDramaRuntime` 做的事，调用方**不用自己做**：

1. 关掉当前所有界面并快照，结束时原样还回来
2. 收起场景 NPC 和地图配置的场景默认UI，结束时还回去
3. 打开剧情面板、装配表现层服务
4. 播完（或被打断）自动收尾：还资源、关面板、恢复界面

重复调用会先掐掉上一段。剧本里的「跳转结束」会自动接着播下一段，不用调用方管。

**播放模式**（正常 / 自动 / 跳过）跨剧本保持，一般不用手动设：

```csharp
DramaManager.Instance.PlaybackMode;                                   // 当前模式
DramaManager.Instance.SetPlaybackMode(EDramaPlaybackMode.Normal);     // 一般由 UI 按钮调
```

## 二、任务 / 条件系统要的查询

```csharp
// 这段剧情完整播完过没有。做前置条件就问它
bool done = DramaManager.Instance.HasDrama(10001);

// 只读集合，调试 / 存档用
IReadOnlyCollection<long> all = DramaManager.Instance.FinishedDramas;
```

- **"完整播完"** = 剧本正常走到头（或走到头之后跳转去了下一本）。**中途退出不算**。
- **每个存档槽独立**，存在 `GameSaveData.FinishedDramaIds`。二周目该重做的任务不会因为
  一周目看过就直接算完成。
- 播完时会发 `QuestEventBus.ReportDialogueFinished(剧情ID)`，**重播也会发** ——
  任务可能是玩家中途才接的，漏报比重报糟。

## 三、存档 / 读档

`DramaManager` 自己实现了 `ISaveable`，存读时会自动带上：剧情进度、对话历史、已播完的剧情。
调用方只需要在**读档后、场景和 UI 就位时**接一行：

```csharp
// 存档里有没有一段没播完的剧情
if (DramaManager.Instance.HasSavedDrama)
{
    DramaManager.Instance.ResumeSavedDrama();   // 已经开播返回 true
}
```

⚠️ **`ResumeSavedDrama` 目前还没接进场景加载流程**，位置要由场景那边定。

恢复的做法是**从剧本开头静默重放到存档点**（等待归零、台词不等输入、选项走存档里的记录），
不是直接跳下标 —— 屏幕上有什么（背景、BGM、立绘站位、对话框皮肤）是前面每条指令堆出来的。

存档点只可能落在**台词**上（那是整段剧情唯一的空闲时刻）：

```csharp
DramaRestorePoint point = DramaManager.Instance.CaptureRestorePoint();   // 没在播返回 null
```

## 四、对话记录（Log）

```csharp
// 打开记录界面。剧情内的 LOG 按钮和剧情外的入口走同一个口子
DramaManager.Instance.ShowDramaLogUI();

// 自己取数据（比如做别的界面）：异步，因为历史里只存了下标，正文要回剧本里现取
List<DramaHistoryLine> lines = await DramaManager.Instance.ResolveHistoryAsync();
foreach (DramaHistoryLine l in lines)
{
    DialogueLine line = l.Line;                 // 和播出时同一个结构
    DramaSpeakerName.TryResolve(line, out string table, out string key);   // 说话人名字的四路寻址
    // line.TextRef / line.VoiceRef 都是多语言引用，交给 LocalizeStringEvent 绑定
}

// 重播某条的语音
DramaManager.Instance.PlayHistoryVoice(line.VoiceRef);
```

- 结果**最老的在前**，UI 一般要倒着排。
- 历史**每个存档槽独立**，滚动保留最近 `DramaHistory.DefaultCapacity`（500）条。
- 存的只有 `(剧本ID, 指令下标, 台词身份)` 三个数，**不存文本** —— 存文本 500 条要 100KB，
  而整个存档才 160KB。剧本改过文案，回看历史也会跟着更新。
- 剧本重导后下标会失效，那时按台词身份找回；实在找不到的条目会被跳过并汇总一条警告。

## 五、已读 / 跳过设置

```csharp
// 设置界面读它画开关
bool onlyRead = DramaManager.Instance.SkipScope == EDramaSkipScope.OnlyRead;

// 玩家改了（这个方法会 PlayerPrefs.Save() 立刻落盘）
DramaManager.Instance.SetSkipScope(EDramaSkipScope.OnlyRead);   // 只跳已读（默认）
DramaManager.Instance.SetSkipScope(EDramaSkipScope.All);        // 全部跳过

// 「重置已读记录」按钮
int n = DramaManager.Instance.ReadLineCount;   // 显示"已读 N 句"
DramaManager.Instance.ClearReadMarks();        // 清空并立刻落盘
```

| 数据 | 存哪 | 作用域 |
|---|---|---|
| 跳过范围开关 | `PlayerPrefs["Drama.SkipScope"]` | 全局偏好，和音量一个性质 |
| 哪些台词读过 | `persistentDataPath/GameSaveData/DramaRead.json` | **跨存档共享**，二周目/换档都还认 |
| 对话历史 | `GameSaveData.DramaHistoryList` | 每个存档槽独立 |
| 已播完的剧情 | `GameSaveData.FinishedDramaIds` | 每个存档槽独立 |

「只跳已读」的判定在每条台词执行**之前**做：撞到没读过的就自动退出跳过，让那句正常播
（语音和打字机都还没开始，玩家看到的就是一句正常台词）。

## 六、场景内容显隐

剧情期间宿主默认把场景 NPC 和地图配置的默认UI 都收起来，结束还原。剧本里的「场景显隐」节点
改的是同一套开关，别的系统也能用：

```csharp
GameSceneManager.Instance.SetSceneNpcVisible(false);       // 收起场景 NPC
GameSceneManager.Instance.SetDefaultSceneUIVisible(false); // 收起场景默认UI

GameSceneManager.Instance.SceneNpcVisible;       // 当前意图
GameSceneManager.Instance.DefaultSceneUIVisible;
GameSceneManager.Instance.CurrentDefaultSceneUI; // 当前场景默认UI 的名字
```

⚠️ **这是"意图"不是一次性动作**。切场景会新建 `SceneController`、重新生成 NPC、重新开默认UI，
所以显隐记在 `GameSceneManager` 上，每次场景就绪时按它重新应用。
自己写"关一次就完"的代码会在切场景后失效。

## 七、事件（想插自己的逻辑就挂这儿）

```csharp
DramaDirector dir = DramaManager.Instance.Director;

// 一条台词即将播出（剧本ID, 台词指令）。读档的静默重放期间不发
dir.TalkStarting += (dramaId, talk) => { /* … */ };

// 一本剧本走到头了（正常播完或播完后跳转；中途退出不算）
dir.DramaFinished += dramaId => { /* … */ };
```

`TalkStarting` 报在指令**执行之前**，所以可以在这里做拦截（"已读跳过"就是这么实现的）。

## 八、扩展：加一条新指令

要给剧情加新能力（比如"播一次音效"），流程在编辑器工程的
`DarmaViewEditor/Docs/剧情系统-加节点到落地全流程.md`，五步：

1. 包里加数据类型（`DramaScript.cs`）
2. 编辑器加节点（`Assets/Drama/Editor/Node/`）
3. 写导出翻译（`Export/DramaNodeExporters.cs`）
4. 包里加 Handler + 注册
5. **本工程**实现 Service（只有第 4 步加了新接口才需要）

本工程这边要落地的服务实现都在 `Assets/Scripts/XFramework/C#/Drama/`，装配点只有两处：
`DramaDirector` 构造函数（资源类）+ 剧情 UI 打开时往 `Director.Context` 塞（表现类）。

**给包的接口加方法是破坏性改动**：本工程可以先把实现写完（多几个不匹配任何接口成员的
公开方法照样编译过），包发布之后自动满足接口，省得留半截代码。

## 九、排错

| 现象 | 原因 |
|---|---|
| `开播失败：剧情表里没有 N` | `DramaData` 配置表里没这一行，或没填 `DramaScriptsPath` |
| `用到了没注册 Handler 的指令：X` | 包版本旧了，或新指令没注册。这是开播前的预检，不是崩溃 |
| `表现层服务还没装配：X` | 剧情 UI 没打开就播 |
| 剧情图里填的ID 和配置表 ID 对不上（警告） | 「进入」节点的剧情ID 该改成配置表 ID。不改也能跑（运行时以配置表 ID 为准），但图上排查会对不上 |
| 对话记录空白 | 上一条的老数据，或者剧本重导后条目全失效了，看控制台的汇总警告 |
| 读档恢复不了剧情 | 存档点的剧情ID 查不到剧本，同上一条 |
| 剧情结束后 NPC 没回来 | 收尾没走到（被异常打断），看控制台 |

调试入口：**Game UITools Editor** 面板，填剧情ID 直接播。
